# 로봇 운영 화면과 작업 상태 동기화

> **쉽게 말하면**
> 
> 로봇이 지금 무엇을 하고 있는지, 왜 멈췄는지, 사람이 무엇을 눌러야 하는지를 한 화면에서 알 수 있게 만든 조작 프로그램입니다. 이번에 고친 건 화면이 이미 끝난 작업을 지금 하고 있다고 잘못 보여주던 문제입니다. 같은 소식이 두 경로로 들어오는데 늦게 온 옛 소식이 최신 소식을 덮어쓰고 있었습니다.

## 문제

작업자가 보는 화면이 **이미 끝난 작업을 지금 하고 있다고 표시**했다.
그 밖에 세 가지가 어긋나 있었다.

- 작업이 바뀌어도 참조 이미지가 늦게 따라왔다
- 백엔드 쪽 화면에서 작업을 시작하면 운전 화면 상태가 초기화되지 않았다
- 일시정지·재개 시점에 화면의 현재 작업이 백엔드가 보고하는 작업과 달랐다

## 검토와 판단

로봇을 실제로 움직이는 컴퓨터와 작업자가 보는 화면 컴퓨터가 따로 있고, 둘은 네트워크로
상태를 주고받는다.

되돌아가는 현상의 원인은 **같은 로그가 두 경로로 들어온다**는 것이었다. 작업 상태 전용
토픽과 공용 로그 토픽은 서로 다른 스트림이라 도착 순서가 보장되지 않는다. 뒤늦게 도착한
공용 로그가 화면을 이미 지나간 작업으로 되돌리고 있었다.

같은 알림을 문자와 우편으로 둘 다 받는데 우편이 며칠 늦게 오면, 이미 알고 있던 최신
상황이 옛 상황으로 되돌아가 보이는 것과 같다.

참조 이미지 문제는 원인이 달랐다. 갱신이 화면 전환이 아니라 **주기적 타이머에 매달려
있던** 탓이었다.

## 한 일

- 전용 상태 토픽이 로그를 한 번이라도 실어 보내면 그 뒤부터 공용 로그의 같은 메시지를
  버리도록 했다. **일시정지·재개 로그는 이 억제에서 제외**했다 — 명시적 일시정지
  이벤트를 보내지 않는 구버전 백엔드와도 계속 붙어야 했기 때문이다.
- 참조 이미지 갱신을 작업 전환 지점 안으로 옮기고, 주기적 타이머는 예비 경로로만 남겼다.
- 백엔드 쪽에서 시작한 경우를 받도록 전체 시작 이벤트에서 화면 워크플로우를 활성으로
  잡게 했다.
- 일시정지·재개 진입 시점에 백엔드가 보고하는 현재 작업으로 화면을 다시 맞추는 경로를
  새로 만들었다.
- 메시지가 한 건도 빠지면 안 되는 채널은 통신 설정을 유실 허용에서 확실 전달로 바꿨다.
- 로봇 제어 콜백이 화면을 멈추지 않도록, 통신 처리를 화면 스레드와 분리했다.

## 화면 설계에서 지킨 것

- 색상만으로 상태를 구분하지 않는다
- 복구 순서를 화면에서 안내한다
- 위험한 동작은 다시 확인받는다
- 화면 크기가 바뀌어도 배치가 무너지지 않는다
- 무료 배포 요건을 고려해 PySide6 를 골랐다

단위 작업마다 "무엇이 잘못될 수 있고, 로봇이 스스로 어떻게 알아채고, 그때 무엇을 하는가"를
표로 정리했다. **물건을 떨어뜨린 경우는 자동 재시도를 하지 않게 했다.** 어디에 떨어졌는지
모르는 상태에서 로봇이 움직이면 더 위험하기 때문이다.

## 결과

실기에서 확인했다. **정량 측정은 하지 않았다.** 복구 시간 단축이나 오조작 감소 같은
수치는 재지 않았으므로 주장하지 않는다.

## 내 기여

화면 구성과 구현, 상태 동기화 문제의 원인 분석과 수정. 현장 피드백을 받아 배치를
개선했다. 로봇 저수준 제어 인터페이스는 별도 담당자가 맡았다.

## 다시 한다면

같은 정보가 두 경로로 들어오는 구조를 처음부터 하나로 정리했어야 했다. 억제 규칙을
덧붙이는 방식은 구버전 호환을 위해 예외를 계속 만들게 된다.
